01 / Problem

Security is complex. The experience cannot be.

Physical access combines organization-specific configuration, identity, nearby hardware, and cryptography. The user should not need to choose a peripheral, interpret BLE state, or understand the protocol to open the right door.

01

Tenant-aware setup

A QR code configures and validates the organization before the user signs in, allowing one app to serve multiple tenants.

02

Correct reader

Nearby devices are filtered by proximity and matched against the reader assigned by the backend—no technical picker required.

03

Native protocol

Android and iOS expose different BLE lifecycles, but both must complete the same secure challenge–response.

02 / Architecture

Shared journey. Native protocol control.

Flutter owns provisioning, account state, and the credential experience. Platform channels hand hardware-sensitive work to Java and Swift, where BluetoothGatt and CoreBluetooth control the exchange.

03 / Hard BLE problem

The edge case was the order of events.

On Android, the reader challenge could arrive before the ID-write callback. Treating one callback order as guaranteed made authentication intermittent across devices, so the flow had to synchronize prerequisites instead of sequence assumptions.

A

Coordinate, do not assume

The native state machine records both the completed write and received challenge, then advances only when both are ready.

B

Keep protocol control native

Challenge-response computation, characteristic writes, and callback sequencing stay below the Flutter UI boundary.

C

Report useful states

The shared layer receives clear progress and failure events so the credential remains understandable during radio or protocol errors.

04 / Result

Native protocol work behind a single credential action.

The product coordinates tenant, identity, proximity, platform BLE behavior, and cryptography behind one focused credential flow.

01

Product outcome

A tenant-aware digital credential with automatic assigned-reader selection and consistent Android/iOS behavior.

02

Engineering outcome

Flutter orchestration with explicit native boundaries for BluetoothGatt, CoreBluetooth, challenge-response work, and order-independent callbacks.

03

Reliability result

Replaced callback-order assumptions with prerequisite-based state coordination, allowing authentication to proceed only after both the credential write and reader challenge were available.
